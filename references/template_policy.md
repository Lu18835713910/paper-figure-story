# PPT模板选择、解析和视觉设计规范（必须执行）

## 优先级与判定

1. 用户明确指定或上传的 **PPTX / POTX 模板**优先；包括已确认可用作模板的示例PPTX。必须分析模板比例、母版、标题与正文页面布局、字体、颜色、留白、页脚和Logo。不得只把默认页面改成同一颜色就声称“沿用了模板”。
2. 用户上传的「旧汇报PPT」如果只用于研究内容参考，不要自动视为可复用的样式模板；询问或根据任务中明确的模板指令判断。
3. 无用户模板：使用 Skill 内置 `assets/default_academic_blue_174994.pptx`，**无Logo**、**16:9宽屏**、**HEX #174994 蓝色学术会议风**。
4. 原论文图/补图不是PPT模板；只用来提供证据和图像来源。
5. 若用户模板与默认配色冲突，**用户模板优先**，不要强制改指定蓝色 #174994；除非用户指明需要重新配色。

## 用户模板接入

- 优先读取 `.pptx`；`.potx` 可尝试转为 PPTX 后继续，检查转换后的版式；旧 `.ppt` 建议先由PowerPoint/LibreOffice转为 `.pptx`，不可默默当作模板完成。
- 展示/整理模板：扫描页面尺寸、slide masters/layouts、占位符、页面类型（封面/过渡/研究思路/图表结果/总结）、形状名称和图像资源；如需准确复用，先渲染样页检查实际视觉，再制作。
- **有明确布局标记的模板**：可使用 `scripts/build_pptx.py --template 用户模板.pptx --template-mode tagged`。模板中应包含命名为 `PFS_LAYOUT_cover`、`PFS_LAYOUT_figure` 等形状和 `PFS_TITLE` 等内容槽位，模板页面作为母页克隆，背景、Logo、修饰元素与布局保留；新内容覆盖对应槽位。
- **普通未标记PPTX模板**：使用 `--template-mode native` 保留母版/版式与页面尺寸、尽量采样标题和强调色；但自动布局只算「适配」，不能保证与每张范例页像素级一致。Codex应结合渲染结果手工选择和重用合适的版式或在模板副本中标记插槽，然后转 tagged 模式；不能直接宣称完全复刻模板。
- 如模板缺少适合Figure的大型图片区域，允许新建同主题结果页，优先保留其配色、标题、页眉页脚和字体体系。
- 有Logo的**用户模板**保留原Logo（除非用户明确要求去除）；**内置默认模板**一律不添加任何机构、期刊、实验室、个人的Logo、水印或品牌标识。
- 不在输出中残留模板原有科研结论、姓名、图片、引文、样本统计等内容；模板引用的视觉装饰与已授权Logo除外。

## 默认模板设计定义

- 屏幕比：16:9（13.333 × 7.5英寸），横版。
- 用户指定主题蓝：`#174994`；亮蓝强调：`#3372C5`；深蓝标题：`#17345E`；淡蓝底：`#EAF1FB`；灰白背景：`#F8FAFD`；白色：`#FFFFFF`；正文灰蓝：`#40536B`。禁止继续沿用旧配色 `#007F8B`。
- 字体：中文首选「微软雅黑」或「思源黑体」；英文字体优先「Aptos/Arial」。替代字体应保证可读、无缺字。
- 层次：封面 30–38 pt，正文结果页标题 24–30 pt，分组标签 16–18 pt，正文优先 15–19 pt，图注/证据来源约 9–11 pt；少文字、强视觉、禁止长段塞满一页。
- 封面：深蓝灰/指定蓝色 #174994对比，大面积留白与简单几何装饰，无Logo。
- 内容：白底/浅灰白底、指定蓝色 #174994章节强调、统一标题和细线分割；科学问题页可用2–3张卡片。
- Figure结果：**原论文图为主要视觉主体（建议占可用面积50–65%）**；另一侧为「问题 / 样本与对照 / 方法与读数 / 关键发现 / 下一问题」，可多页拆分。保留坐标、panel字母、统计标记、图例，不能改图中数值。每页保留 `Fig/panel + 论文页码` 来源。
- **总框架图：不得采用Figure逐页使用的固定纵向文字链，也不采用固定水平五步链**。依据论文的证据结构选择并行分支、合流、比较、独立验证、反馈或确属顺序的线性图。节点文字应是具体的科学问题、样本/实验设计及结果，而不是“现象/机制/验证”等空泛占位。所有节点、文字、箭头均须可编辑。
- **技术路线：真实的实验拓扑图**。分组、重复、时间点与平行方法按研究实际对应，不能用箭头误暗示“先RNA-seq、后ATAC-seq、再Hi-C”。
- 关系边需标识为“原文支持”或“汇报结构性连接”，后者用虚线。关系图是研究论证的示意图，非分子相互作用的直接证明。
- 结论页：3–4条结果及证据强度，分开写局限；没有功能实验时不画“验证因果”箭头。
- 页脚：论文简短引文 + 可选页码；不要把完整DOI和长文献写进主画面。

## 内容转视觉的正确顺序

1. 先完成科研逻辑和Figure证据核查，再定每页讲述目标和图形内容。
2. 明确Slide ↔ Fig/panel映射，选择支持该页结论的面板并从原PDF高分辨率导出（注意裁图不得去掉重要图例和坐标）。
3. 读取模板并匹配其已有的封面/正文/结果/总结版式，调整内容长度以适合模板；**禁止为塞进模板而删掉必要样本、对照或改变科研结论**。
4. 生成可编辑 `.pptx`，图像作为独立插入素材；文本、框架、箭头、标注仍然可编辑。
5. 导出预览PDF/PNG或使用PowerPoint检查，逐页查：文字溢出、图片变形、面板裁剪、颜色对比、来源缺失、旧内容泄漏、Logo规则、总页数。
6. 必须给出模板使用记录：用户模板文件名/默认模板、选用版式、字号/比例变化、保留或剔除的元素，及任何无法原样继承的细节。

## 生成器接口与边界

`scripts/build_pptx.py` 读取 `06_PPT页面数据.json`，可设置 `--template 路径`、`--template-mode auto|tagged|native`、`--output 路径`。其中 `tagged` 实现高保真布局/装饰元素的原样复用，`native` 使用用户母版和风格采样进行自动适配。默认使用内置指定蓝色 #174994模板。

生成器仅负责**把已核实的PPT数据排成可编辑演示文稿**。它不会自动识别PDF Figure、不会自行替用户核实统计和实验设计；这些由本Skill的阅读、证据链拆解与图片导出步骤完成。

## 总框架参考布局

优先依据 `overall_framework_policy.md` 的模块化联合框架规则：研究对象 / 实验分组与时间 / 核心技术（每项附科研问题） / 补充验证与功能检验 / 总体机制或规律。全局总图不按Figure编号线性拼接。
